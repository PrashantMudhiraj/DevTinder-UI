01 What is the Virtual DOM and how does it work? Core
The Virtual DOM (VDOM) is a lightweight in-memory representation of the real DOM. React keeps this JS object tree in sync with the actual browser DOM via a process called reconciliation.

How it works (3 steps):
  1. Render: When state/props change, React re-renders a new Virtual DOM tree.
  2. Diff: React compares the new VDOM with the previous snapshot using the diffing algorithm.
  3. Patch: Only the changed nodes are updated in the real DOM (batched and optimized).
💡 The real DOM is slow to update because changes trigger reflows/repaints. VDOM batches updates and minimizes direct DOM access.
// React builds a VDOM like this internally:
const vdom = {
  type: 'div',
  props: { className: 'app' },
  children: [
    { type: 'h1', props: {}, children: ['Hello'] },
    { type: 'p',  props: {}, children: ['World']  }
  ]
}
// After state change, new VDOM is diffed against old one
// Only changed DOM nodes are updatedJS

02 What is React Fiber and what are its benefits? Core
React Fiber is a complete rewrite of React's core reconciliation engine (introduced in React 16). The old reconciler was synchronous and couldn't be interrupted — causing dropped frames on heavy updates.

Fiber makes rendering incremental and interruptible:
  • Time-slicing: Breaks rendering into small chunks, yielding to the browser between them.
  • Prioritization: High-priority updates (user input) can interrupt low-priority ones (data fetching).
  • Pause/Resume: Work can be paused, aborted, or restarted.
  • Concurrent Mode: Enables features like Suspense, useTransition, and useDeferredValue.
💡 Each fiber is a unit of work — a JS object representing a component instance with its state, props, effects, and a pointer to its parent/child/sibling.

03 What is JSX? Why can't browsers read it directly? Core
JSX (JavaScript XML) is a syntax extension that lets you write HTML-like code inside JavaScript. Browsers don't understand JSX — it must be transpiled to regular React.createElement() calls by Babel. 
// JSX (what you write)
const element = (
  <div className="box">
    <h1>Hello</h1>
  </div>
);

// After Babel transpilation (what browser runs)
const element = React.createElement(
  'div',
  { className: 'box' },
  React.createElement('h1', null, 'Hello')
);JSX
💡 In React 17+, you no longer need to import React in scope just for JSX — the new JSX transform handles it automatically.

05 Explain React's Reconciliation Algorithm. Core
Reconciliation is the process React uses to update the DOM efficiently. It uses a heuristic O(n) diffing algorithm based on two assumptions:
  1. Two elements of different types will produce different trees (unmount and remount).
  2. The developer can hint which child elements are stable across renders using the key prop.

Rules:
  • Same type → update props, recurse into children
  • Different type → destroy old tree, build new one
  • Lists → use key to match elements across renders
⚠️ Never use array index as key for dynamic lists — it breaks reconciliation when items are reordered or deleted.

06 What is one-way data binding in React? Core
In React, data flows in one direction: parent → child through props. This is called unidirectional data flow.

To send data upward, a parent passes a callback function as a prop, and the child calls it. 
function Parent() {
  const [name, setName] = useState('');
  return <Input value={name} onChange={setName} />;
}

function Input({ value, onChange }) {
  return (
    <input
      value={value}
      onChange={e => onChange(e.target.value)}
    />
  );
}JSX
💡 This makes debugging easier — you always know where data comes from and who changes it.

09 What are Controlled vs Uncontrolled components? Components
Controlled: Form data is handled by React state. The input value is driven by state.
Uncontrolled: Form data is handled by the DOM itself. You read the value via useRef. 
// Controlled — React owns the value
function ControlledInput() {
  const [val, setVal] = useState('');
  return <input value={val} onChange={e => setVal(e.target.value)} />;
}

// Uncontrolled — DOM owns the value
function UncontrolledInput() {
  const inputRef = useRef();
  const handleSubmit = () => console.log(inputRef.current.value);
  return <input ref={inputRef} />;
}JSX
💡 Controlled = single source of truth (recommended). Uncontrolled = useful for third-party DOM integrations.

11 What is the difference between React.memo and PureComponent? Components
Both prevent re-renders when props haven't changed, but they apply to different component types:
  • PureComponent — for class components, does shallow comparison of props and state
  • React.memo — for functional components, does shallow comparison of props only
// React.memo for functional components
const Child = React.memo(function Child({ name }) {
  console.log('Rendered');
  return <p>{name}</p>;
});

// Custom comparison function (optional)
const Child = React.memo(Child, (prevProps, nextProps) => {
  return prevProps.id === nextProps.id; // true = skip re-render
});JSX
⚠️ React.memo only does a shallow comparison. Objects/arrays passed as props must have stable references (use useMemo/useCallback).

15 Explain useState and useEffect with examples. Hooks
useState adds state to a functional component. Returns [value, setter].

      .then(r => r.json())
      .then(data => { if (!cancelled) { setUser(data); setLoading(false); }});

    return () => { cancelled = true; }; // cleanup
  }, [userId]); // re-run when userId changes

  if (loading) return <Spinner />;
  return <p>{user.name}</p>;
}JSX

16 useMemo vs useCallback — what's the difference? Hooks

useMemo

  • Memoizes a value
  • Returns computed result
  • For expensive calculations
  • useMemo(() => compute(), [deps])

useCallback

  • Memoizes a function
  • Returns stable function ref

17 What is useRef and when do you use it? Hooks
useRef returns a mutable object with a .current property that persists across renders. Changing .current does NOT trigger a re-render.

Two main uses:
  1. DOM access — focus input, measure element
  2. Mutable values — store previous value, interval ID, timer
// Use 1: DOM access
const inputRef = useRef(null);
<input ref={inputRef} />
inputRef.current.focus();

// Use 2: Mutable value (no re-render on change)
const timerId = useRef(null);
useEffect(() => {
  timerId.current = setInterval(() => tick(), 1000);
  return () => clearInterval(timerId.current);
}, []);

// Use 3: Capture previous value
const prevCount = useRef(count);
useEffect(() => { prevCount.current = count; });JSX

20 What are custom hooks? Write a useFetch example. Hooks
Custom hooks are functions that start with use and can call other hooks. They extract reusable stateful logic out of components. 
// Custom useFetch hook
function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    setLoading(true);
    fetch(url)
      .then(r => r.json())
      .then(setData)
      .catch(setError)
      .finally(() => setLoading(false));
  }, [url]);

  return { data, loading, error };
}

// Usage
function Users() {
  const { data, loading, error } = useFetch('/api/users');
  if (loading) return <Spinner />;
  return <UserList users={data} />;
}JSX

21 What are the Rules of Hooks and why do they exist? Hooks
There are two rules:
  1. Only call Hooks at the top level — not inside loops, conditions, or nested functions.
  2. Only call Hooks from React functions — function components or custom hooks.

Why? React relies on the order of hook calls to associate each hook with its state. If hooks are called conditionally, the order can change between renders, breaking React's internal tracking. 
// ❌ Wrong — inside condition
if (condition) {
  const [x, setX] = useState(0); // breaks hook order!
}

// ✅ Correct — always called
const [x, setX] = useState(0);
if (condition) { /* use x here */ }JSX

23 How do you optimize React app performance? Performance
Key optimization strategies:

25 What causes unnecessary re-renders? How to avoid them? Performance
Causes:
  • Parent re-renders → all children re-render by default
  • New object/array/function created inline in JSX each render
  • Context value changes affect all consumers
  • setState called with same value (React 18 bails out for primitives)
Solutions: 
// ❌ New function on every render
<Child onClick={() => doThing(id)} />

// ✅ Stable reference with useCallback
const handleClick = useCallback(() => doThing(id), [id]);
<Child onClick={handleClick} />

// ❌ New object on every render
<Child style={{ color: 'red' }} />

// ✅ Memoized object
const style = useMemo(() => ({ color: 'red' }), []);
<Child style={style} />JSX

Both are React 18 Concurrent Mode hooks for handling expensive updates without blocking the UI.

30 Explain Redux flow: Action → Reducer → Store → View State
Redux follows a strict unidirectional data flow:
  1. Action — Plain JS object describing what happened: { type: 'ADD_ITEM', payload: item }
  2. Dispatch — Sends the action to the store: dispatch(action)
  3. Reducer — Pure function: (state, action) => newState
  4. Store — Holds state, notifies subscribers
  5. View — Re-renders with new state via useSelector
// Redux Toolkit (modern Redux)
const cartSlice = createSlice({
  name: 'cart',
  initialState: [],
  reducers: {
    addItem: (state, action) => { state.push(action.payload); },
    removeItem: (state, action) => {
      return state.filter(item => item.id !== action.payload);
    }
  }
});

export const { addItem, removeItem } = cartSlice.actions;JSX

If useEffect returns a function, React calls it:

  • When the component unmounts

43 What are Error Boundaries? Advanced

  static getDerivedStateFromError() {
    return { hasError: true };
  }

    logErrorToService(error, info.componentStack);
  }

  render() {
    if (this.state.hasError) {
      return <h2>Something went wrong.</h2>;
    }
    return this.props.children;
  }
}

52 What is the difference between <script>, async, and defer? HTML5
These control when a script is fetched and executed relative to HTML parsing:
  • Normal <script> — HTML parsing pauses, script fetches + executes, then parsing resumes. Blocks rendering.
  • async — Script fetches in parallel. HTML parsing pauses only when script executes. Order not guaranteed. Good for independent scripts (analytics).
  • defer — Script fetches in parallel but executes only after full HTML parsing. Order preserved. Best for most scripts.
<!-- Blocks HTML parsing ❌ -->

<!-- Parallel fetch, executes immediately when ready -->
<script src="analytics.js" async></script>

<!-- Parallel fetch, executes after HTML parsed ✅ -->
<script src="app.js" defer></script>HTML
💡 Best practice: put scripts in <head> with defer so they load early but don't block rendering.
